### Executive Summary

Arrakis Security released its 2026 Autonomous Agents Threat Report, analyzing telemetry from thousands of enterprise production agents. The report reveals widespread governance and operational security gaps, notably that 76% of active enterprise agents sit dormant for at least 60 days while retaining functional credentials and active triggers. 

This exposure is compounded by external accessibility and internal permission design flaws. A significant portion of these unmonitored agents can be triggered from outside the enterprise perimeter or leveraged to bypass access controls, presenting an unmanaged attack surface for organizations using autonomous agent architectures.

### Technical Impact & Root Cause

The primary root cause of this vulnerability profile is the absence of lifecycle management and explicit ownership for autonomous agents. While enterprise offboarding processes systematically revoke access for departing human employees, retired or unused software agents are rarely decommissioned, leaving permanent credentials, triggers, and approvals fully operational indefinitely.

The technical impacts identified in production telemetry include:
* **Dormant Credentials & Triggers:** 76% of active agents have not executed a task in 60 days, and 44% have been inactive for over 180 days, yet their API keys and triggers remain fully armed.
* **Unauthenticated External Execution:** 24% of dormant agents can be awakened and executed by an unsigned webhook originating outside the organization.
* **Privilege Escalation & Cross-Agent Data Retrieval:** 20% of agents can delegate tasks to secondary agents with higher permission levels and receive outputs that the initiating agent is not independently authorized to produce.

### Mitigation & IOCs

To mitigate risks associated with dormant and vulnerable agents, organizations should implement the following architectural controls:
* Enforce runtime governance controls that require signed human authorization for consequential agent actions.
* Implement mandatory expiration limits on all agent credentials, API keys, and task approvals, ensuring expired states default to denied.
* Inspect all incoming inbound content prior to agent processing, enforcing a strict distinction where external inputs are treated purely as data rather than actionable commands.
* Configure agent runtimes and licensed installs to enter a secure locked state upon operational inactivity rather than remaining fully armed.
