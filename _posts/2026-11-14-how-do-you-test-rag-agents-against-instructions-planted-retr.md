### Executive Summary

Discussions within the cybersecurity community highlight indirect prompt injection as a key attack vector against Retrieval-Augmented Generation (RAG) agents. While traditional security evaluations focus primarily on direct user inputs, RAG agents are exposed to instructions embedded within retrieved knowledge sources, such as support documents, emails, web pages, and tickets. 

Security practitioners advocate for testing RAG agents using control payloads placed inside test knowledge bases. By embedding harmless instructions (e.g., forcing a specific output phrase like "PINEAPPLE") into documents expected to be retrieved by target queries, analysts can evaluate whether an agent processes untrusted data as executable instructions. If the canary phrase leaks into agent responses, it indicates a vulnerability to malicious indirect prompt injections.

### Technical Impact & Root Cause

The root cause of indirect prompt injection in RAG architectures stems from the model's inability to strictly isolate executable instructions from retrieved data within the context window. When retrieved content contains natural language commands, language models may execute those commands alongside or over top of original system directives.

If an agent fails to separate retrieved context from its operating parameters, an adversary can manipulate indexed repository data or third-party API outputs to control agent behavior. Technical impacts include payload execution, compromised response integrity, and potential unauthorized actions taken by the agent when interacting with internal data or external tools.

### Mitigation & IOCs

To evaluate and reduce exposure to indirect prompt injection in RAG environments, organizations should consider the following controls:
* Conduct baseline testing using harmless, detectable instructions inside test knowledge bases to verify whether context leaks into model behavior.
* Implement structural prompt engineering techniques, such as explicit data delimiters and system-level context framing that instructs the model to treat retrieved context strictly as passive data.
* Apply content sanitization pipelines to retrieved documents and third-party API outputs prior to appending them into prompt contexts.
