### Executive Summary
Threat actors are deploying a malicious updater to compromise Linux servers running Control Web Panel (CWP). The attack replaces the legitimate `cwpsrv` web-server binary with a trojanized version, leaving a dormant backdoor on affected systems.

While over 340,000 CWP instances have been observed exposed to the internet, the exact number of infected servers remains unknown. Researchers have confirmed evidence of real-world compromises resulting from this activity.

### Technical Impact & Root Cause
The root cause of the compromise stems from the execution of a malicious updater that replaces the legitimate `cwpsrv` binary with a trojanized variant. The backdoor remains inactive until threat actors send specially crafted HTTP requests containing encrypted commands to trigger execution.

To evade detection, the malware (referred to as CWPdoor) suppresses the logging of malicious HTTP requests, restores modified file timestamps, deletes installation evidence, and encrypts command communications. Successful compromise grants threat actors unauthorized access to administrative functions, hosted websites, databases, email services, and adjacent server infrastructure.

### Mitigation & IOCs
System administrators should immediately audit CWP deployments using the following steps:
* Search for suspicious `cwpsrv` processes running on the host.
* Inspect servers for the presence of the `ngx_http_integrity_helper` socket.
* Check the server binary for `X-Ngx-Integrity` strings.
* If a compromise is confirmed, replace the trojanized binary, update the CWP software, rotate all server and service credentials, and investigate the environment for secondary malware.
