### Executive Summary
A community technical discussion details the architecture and operational challenges of an eBPF/XDP-based DNS flood mitigation system. The implementation focuses on dropping malicious traffic at the kernel level while attempting to maximize legitimate DNS query success during high-volume distributed denial-of-service (DDoS) attacks.

The primary limitation identified in the design is that high-volume distributed attacks utilizing thousands of distinct source IPs can saturate global rate-limiting capacity. As a result, legitimate DNS queries are dropped even when individual client traffic remains within normal rate thresholds.

### Technical Impact & Root Cause
The current system architecture processes traffic at the XDP layer using minimal Ethernet, IPv4, UDP, and DNS header validation. Per-source rate limiting relies on the Generic Cell Rate Algorithm (GCRA) using atomic operations, with state tracking maintained in an Least Recently Used (LRU) hash map. Global traffic thresholds are enforced via a shared token bucket protected by a spinlock.

The root cause of query drops for legitimate users stems from global capacity exhaustion. During a distributed flood, new or spoofed attacking IPs reserve global capacity before individual source state checks or insertions complete, depleting the global token bucket. While potential fixes like adaptive rate limits, source reputation tracking, and DNS response feedback loops exist, implementing them at the XDP driver level adds state complexity, memory overhead, and CPU latency per packet.

### Mitigation & IOCs
Architectural mitigations currently under evaluation to balance throughput and legitimate query success include:
* Implementing adaptive rate-limiting algorithms to dynamically adjust thresholds based on traffic conditions.
* Tracking source history and reputation to prioritize established, benign clients.
* Incorporating feedback from downstream DNS server responses into XDP admission decisions.
