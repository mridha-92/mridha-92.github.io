### Executive Summary

An open-source prototype for a self-hosted Layer 7 Web Application Firewall (WAF) named Aethel Core has been developed using SWI-Prolog. Created by developer `/u/lokinpendawa`, the project utilizes SWI-Prolog's Just-In-Time Indexing (JITI) rather than traditional C, Go, or Python frameworks.

Despite skepticism regarding Prolog's speed and thread contention handling, the developer reported significant initial adoption on GitHub. Within a 14-day window, the repository recorded 191 total clones, 88 unique cloners, and approximately a 61% visitor-to-clone conversion rate.

The open-source GitHub prototype is currently frozen. The developer is transitioning the core features into an obfuscated standalone production runtime aimed at deployment within local ERP and SaaS networks.

### Technical Impact & Root Cause

Aethel Core relies on SWI-Prolog JITI indexing to evaluate Layer 7 application traffic rules. The project's primary technical differentiator is its execution environment, departing from typical C-based regex evaluation engines and high-level language web proxies.

To mitigate Distributed Low-and-Slow DDoS attacks, the developer built a custom Global Traffic Shaving module called `wave_shaver`. This feature is designed to inspect and rate-limit abusive low-rate request streams before they impact downstream services.

The codebase is being migrated from the open-source prototype to an obfuscated standalone production runtime built via SWI-Prolog's `class(runtime)` engine. This runtime is intended for direct integration into production ERP and SaaS infrastructure.

### Mitigation & IOCs

Security teams evaluating or testing the prototype are advised to manually audit the open-source Prolog logic available in the project repository before introducing it into testing or staging environments.
