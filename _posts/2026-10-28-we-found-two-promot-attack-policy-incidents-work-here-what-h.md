### Executive Summary
Security monitoring at a healthcare organization identified multiple "PROMPT_ATTACK" policy violations during routine developer interactions with Large Language Models (LLMs). The security event was detected following the implementation of prompt monitoring controls using a third-party platform.

Initial triage confirmed that standard prompts submitted by developers and product managers were being automatically modified by local open-source plugins. These plugins appended context instructions containing aggressive language designed to override LLM behavior, triggering automated security blocks.

### Technical Impact & Root Cause
The root cause was traced to open-source developer plugins integrated into the development workflow, specifically named SuperPowers and BMAD. Whenever standard user prompts were submitted, the plugins automatically concatenated their internal skill instructions onto the outgoing user request.

The SuperPowers plugin contained explicit directive override text aimed at forcing LLM compliance, specifically stating: `"YOU DO NOT HAVE A CHOICE. YOU MUST USE IT. This is not negotiable"`. The third-party platform, looplabs.run, flagged this injected payload as a prompt attack, halting execution and returning a `PROMPT_ATTACK` policy error message to the user.

### Mitigation & IOCs
Recommended mitigations based on the incident report include:
*   Maintain active prompt inspection mechanisms to detect concatenated user and plugin inputs prior to LLM execution.
*   Conduct code and content audits on open-source plugins (such as SuperPowers and BMAD) to evaluate hidden prompt structures and prevent unauthorized LLM instruction overrides.
