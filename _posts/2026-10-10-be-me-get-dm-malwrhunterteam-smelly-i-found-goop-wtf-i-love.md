### Executive Summary

Threat researchers from malwrhunterteam and smica83 discovered a fake Point-of-Sale (POS) update installer targeting ToastPOS systems, a software platform primarily used in the restaurant industry. The payload, uploaded to MalwareBazaar, disguises itself as a legitimate update package to gain initial execution on victim devices.

The malware contains multi-faceted data-exfiltration capabilities, including memory scraping for payment card details, database dumping, and lateral terminal discovery. Additionally, it embeds a secondary executable and steals stored web credentials from Google Chrome.

### Technical Impact & Root Cause

The initial infection vector relies on the execution of a malicious Windows Installer file named `POS_System_Update.msi`. When launched, the installer extracts an internal DLL file and executes a function named `EdgeUpdateMain`. The malware collects system telemetry to register the compromised host and initiates outbound C2 communications to a fake POS update domain (`toastposupdate(.)com`). Network requests require a specific hardcoded User-Agent string (`opbZMeJMJZmmveM7Nnck3g`) to establish a valid connection.

The threat software exhibits entirely unobfuscated code and inconsistent communication routines. In some components, it leverages native Windows WinAPI functions (`WinHTTPConnect`, `WinHTTPOpenRequest`, `WinHTTPSendRequest`), while in others, it invokes system-level `cURL` commands with POST parameters. Once connected to the C2 server, the payload can execute specific remote commands:
* `db_dump`: Dumps the full contents of the local POS database.
* `ram_scrape`: Scrapes host system memory to capture credit card data.
* `intercept`: Identifies and scans for additional POS terminals on the network.

### Mitigation & IOCs

To mitigate risk from this threat, organizations running ToastPOS software should enforce strict software-installation policies, prohibiting unauthorized `.msi` executions. Security teams should monitor endpoint activity for unexpected child processes originating from Windows Installer routines, specifically looking for native `cURL` execution and unauthenticated database access commands. Network perimeters should filter and log traffic targeting unauthorized external domain infrastructure or matching anomalous User-Agent signatures.
