### Executive Summary

An open-source phishing URL detector named Phisguard has been released on GitHub by developer /u/Rough_Card9926. Trained and evaluated against a dataset of approximately 15,000 verified PhishTank URLs, the tool performs static text-based analysis on links without initiating outbound network connections to visit target websites.

Analysis of the dataset revealed that `docs.google.com` was the most frequent phishing host, followed closely by free hosting infrastructure such as Firebase and 000webhost. Because threat actors heavily leverage high-reputation, legitimate domains, traditional domain-reputation scoring systems frequently fail to catch these malicious links.

The current iteration of the detector achieves an estimated 90% catch rate on previously unseen phishing sites while maintaining a false positive rate under 2%. The developer emphasized tuning down false alarms to prevent alert fatigue, noting that earlier builds erroneously flagged legitimate paths such as `github.com/login`.

### Technical Impact & Root Cause

The underlying threat vector relies on simple URL obfuscation and structural manipulation techniques. Common methods identified in the dataset include typosquatting (e.g., `paypa1.com`), brand-spoofing subdomains (e.g., `paypal.com.account-verify.xyz`), punycode/homograph look-alikes, and user-authentication syntax abuse where browsers ignore strings preceding the `@` character (e.g., `google.com@evil.ru`).

Static URL analysis faces explicit limitations when encountering compromised legitimate websites. For instance, when threat actors deploy a phishing kit inside deep subdirectories of a hacked small-business site (such as `/wp-includes/`), the top-level URL structure retains a legitimate appearance, making detection difficult through URL text alone.

From a model design perspective, root causes for early false positives stemmed from over-generalizing login path strings. Generic authentication endpoints on trusted platforms triggered heuristics designed to flag credential-harvesting keywords, necessitating model tuning to lower false alarm rates below 2%.

### Mitigation & IOCs

Security teams and analysts can reference or utilize the open-source detection project hosted at `https://github.com/1amaaaal/Phisguard`. The tool provides explainable output detailing why a given link was flagged. Organizations targeting abuse on legitimate platforms (e.g., Google Docs, SharePoint, Firebase) must rely on inspection capabilities beyond simple domain blocking, as blocking host domains impacts legitimate business operations.
