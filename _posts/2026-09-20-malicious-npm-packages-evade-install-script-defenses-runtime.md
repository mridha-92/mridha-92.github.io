### Executive Summary
An ongoing supply chain malware campaign has been observed abusing the npm package repository using a package named `indexed-btree`. Threat actors are bypassing conventional software supply chain security controls by shifting malicious code execution from package installation hooks to standard runtime behavior.

By embedding malicious execution within the package's normal runtime function, the campaign successfully evades traditional defenses that focus primarily on detecting or blocking suspicious installation scripts. Organizations evaluating packages solely on install-script telemetry remain vulnerable during application deployment.

### Technical Impact & Root Cause
The root cause of this evasion strategy relies on avoiding npm lifecycle scripts (such as `preinstall` or `postinstall`). Instead, the malicious payload is designed to activate only when the package is imported and invoked by a host application during normal execution.

The primary technical impact is the failure of automated install-script security controls to flag or stop the malicious package upon download. Consequently, the payload executes undetected in the runtime context of any application that incorporates the `indexed-btree` package.

### Mitigation & IOCs
Software development teams should review dependency trees to identify and remove the `indexed-btree` package. Security reviews should extend beyond installation script analysis to include runtime behavior monitoring and static code analysis of third-party package imports.
