### Executive Summary

LiteLLM revealed that an Agent Platform master key was inadvertently exposed in a public GitHub repository in late May 2026. This credential leak enabled an unauthorized threat actor to compromise the project's infrastructure.

The security breach ultimately allowed the attacker to steal GitHub tokens and hijack the project's release pipeline, resulting in the distribution of a malicious version of the popular LiteLLM Python package.

### Technical Impact & Root Cause

The root cause of the incident traces back to May 27, 2026, when a configuration file containing the master key for an Agent Platform deployment was committed to the public `LiteLLM-Labs/lite-harness` repository.

Leveraging this exposed master key, the threat actor gained access to the deployment environment. The attacker harvested GitHub tokens from the system and subsequently compromised the build and release pipeline to publish a malicious package update.

### Mitigation & IOCs

Specific remediation actions taken by the maintainers are not detailed in the provided excerpt. Organizations using LiteLLM should audit their environments for compromised versions, revoke affected credentials, and ensure secret-scanning mechanisms are active across all public repositories.
