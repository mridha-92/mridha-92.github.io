### Executive Summary
An audit of out-of-the-box Google SecOps (Chronicle) curated detections for Office 365 (O365) and User and Entity Behavior Analytics (UEBA) has identified multiple logic flaws and hardcoded thresholds. These underlying bugs cause production alert floods by incorrectly grouping user events and failing to account for legitimate user activities.

The affected rules include detections tied to threat activity like APT29/BRICKSTORM, network roaming on mobile devices, delegation in shared mailboxes, and authentication anomaly baselines. Security researcher /u/allexj has released custom drop-in YARA-L rule replacements to resolve these deficiencies.

### Technical Impact & Root Cause
* **Session vs. Application ID Grouping:** The O365 Multiple User Agents rule (linked to APT29/BRICKSTORM) groups events purely by `$application_id` across a 3-hour window instead of grouping by `$session_id`. This aggregates unrelated users across the organization and triggers false positives.
* **Missing Outlook Mobile Exclusions:** O365 rules monitoring IP/ASN changes on `ClientAppId` omit an exclusion for the official Microsoft Outlook Mobile App GUID (`27922004-5251-4030-b22d-91ecd9a37ea4`), creating alerts every time a mobile user switches between Wi-Fi and cellular networks.
* **Shared Mailbox Collision:** Rules attempt to identify Service Principals strictly by checking if `$principal.user.userid != $target.user.userid`. This triggers an alert whenever a human user accesses a shared or delegated inbox.
* **Hardcoded UEBA Variable:** The Anomalous Auth Attempts Total rule sets `$num_stddevs_away = max(2)` in the outcome block, but hardcodes the value 2 inside `$historical_threshold`, preventing custom variable overrides from taking effect.

### Mitigation & IOCs
* Replace broken native rules with custom YARA-L drop-in fixes available via the GitHub repository: `https://github.com/All3xJ/fixing-google-secops-detections`.
* Update the O365 Multiple User Agents match block logic to evaluate `$application_id, $session_id over 3h`.
* Add explicit exclusions for the Microsoft Outlook Mobile App GUID (`27922004-5251-4030-b22d-91ecd9a37ea4`) to ClientAppId IP/ASN tracking rules.
* Adjust shared mailbox detection logic to properly differentiate between human access to delegated mailboxes and actual Service Principal activity.
