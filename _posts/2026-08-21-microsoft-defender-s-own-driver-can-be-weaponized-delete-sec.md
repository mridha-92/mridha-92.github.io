### Executive Summary
Check Point Research has disclosed a technique detailing how Microsoft Defender's legitimate boot-time remediation driver can be weaponized to manipulate system files and registry keys. The methodology allows arbitrary kernel-level actions without relying on a software vulnerability or importing third-party drivers.

The technique affects a wide range of Microsoft operating systems, spanning from Windows 7 through Windows 11 25H2. Because the mechanism leverages an existing, legitimately signed system component, it circumvents standard security controls designed to catch external driver deployment.

### Technical Impact & Root Cause
The root cause involves abusing Microsoft Defender's Boot Time Removal Tool driver, `BTR.sys`. Designed for boot-time system remediation, the driver's elevated execution rights can be repurposed to perform arbitrary file and registry modifications at the kernel level.

The primary impact is that attackers can abuse `BTR.sys` during the system boot sequence to terminate or delete security software. Because the driver is already present on the target host and digitally signed by Microsoft, adversaries can achieve kernel-level persistence and tampering without bringing a vulnerable driver (BYOVD) or exploiting a software flaw.

Specific remediation guidance or patches from the vendor are not provided in the source text. Defenders should monitor for unexpected execution routines or unauthorized configuration changes referencing the `BTR.sys` driver during system startup.
